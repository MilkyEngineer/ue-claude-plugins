# Changelog

## 0.4.1

### Fixed

- **`uak mutate` could leave the mutant in the binaries, silently.** UBT counts a direct prerequisite of an action, such as a source file compiled on its own, as newer than its output only when it is more than a second newer ("allow a 1 second slop", `ActionGraph.cs`, in `Actions/` since UE 5.8, in `System/` before; a file from a dependency list, such as a header or a source in a unity file, counts as soon as it is newer), and the restore could write a file back within a second of the object the mutant build wrote (observed: object at 18:55:37.633, source at 18:55:37.859). The object then counted as up to date: the rebuild and every later build skipped it, `uak build` said up to date, and the editor kept running the mutant while the source was clean. Now, once the files are back (at the end of a check, and in `uak mutate -restore`), uak waits for running `uak compile`s, takes the newest of this machine's clock, the clock of the file system the files are on (a file written beside them and read back) and the binaries the mutant build wrote, and gives each file it put back a write time 2 s past that, waited out (at most 60 s; a time further ahead is set all the same), so the rebuild recompiles them and everything that includes them; it checks that the time took, and only then rebuilds. The bytes and the read-only flag are unchanged; where a time can't be set, the file's own bytes are written whole instead. A stamp that fails or doesn't take leaves the journal, with nothing rebuilt, and exits 5: `-restore` stamps again. A journal 0.4.0 left with its files back is stamped by `-restore` before it rebuilds, which also records its build, so a `uak build` can clear it. A rebuild's "succeeded" isn't taken on trust: an up-to-date build keeps the mutant's objects, so a journal clears only once builds since the stamp show a compile of each patched file the mutant build compiled (a header by any compile; a compile that failed doesn't count) and one succeeds; without that it stays (`BINARIES PENDING`, below), `-restore` stamps again, and `-restore -force` is the way out for a file no build compiles. `-restore -accept` of a journal uak can't read stamps the files it can still name and refuses a rebuild that compiled nothing: a file copied back from its `.orig` keeps an old write time, so give it a new one.
- **A rebuild that failed on another file blocked everyone.** When the restore's rebuild failed (another agent's half-edited file), the check exited 5 and left its journal, so `uak test` and `uak lock run` refused for everyone, and `uak mutate -status`, `uak vcs shelve` and `uak horde preflight -shelve` too, until someone ran `-restore` on a tree that builds, though the files were back byte for byte. Now the verdict stands (exit 0, 6, 3 or 4, not 5). Just before the mutant build, uak notes the target's binaries (the code files in the folders of the editor target's receipt, `Binaries/<Platform>/<Target>.target`, and in each project plugin's `Binaries/<Platform>`), and it reads that list again after the build; once the files are back, the ones that changed are those the mutant build wrote, and what the build says it linked is checked against them. UBT goes on after an error, so a build that failed elsewhere may still have linked the mutant. When none of them may still hold the mutant (it linked nothing, or each was linked after the stamp, from the recompiled files, or is gone), the journal is cleared. Else, or when which it wrote isn't known (no receipt, a link outside those folders, or a patch that adds or deletes a file or changes a `.Build.cs`, `.Target.cs`, `.uplugin` or `.uproject`), a `BINARIES PENDING` line says which binaries may hold the mutant (`BinariesPending` in `-resultfile`), and the journal stays, its files back and stamped: `uak test`, `uak lock run` and `uak mutate` refuse until a `uak build` of the editor target (without UBT arguments) that recompiled them succeeds, which clears it, or until those binaries are rewritten, when the next of them clears it; `uak build` and `uak compile` run, and since the tree holds no mutation, `uak mutate -status` exits 0 (listing it as a warning) and shelves and preflights go ahead, but for a shelf that holds such a binary, which is refused. `-restore` exits 0 when a failed rebuild leaves no binary that may hold the mutant, and 5 while one may. Mixed versions are safe: 0.4.0 reads a 0.4.1 journal as it read its own (a journal whose files are back waits for `-restore`).
- **A patch made in a Git work tree below the project was refused.** Patch paths had to be relative to the workspace root uak finds at or above the project (or the project folder), so a `git diff` made in a plugin's own repository named files that weren't there. When a file the patch changes isn't under that root, but every one is under exactly one Git work tree below the project (at most three folders down), uak now takes the paths under it and applies the patch there with `git apply`, and says so. A patch whose files fit no work tree, or several, is still refused.

- **A kept record of a dead holder's command could refuse `uak mutate` and `-restore` for good**, and so leave a mutant in the tree: a zombie, or a reused PID whose start time can't be read, never reads as gone. `uak lock forget-orphan -hold=<id>` drops that record under the lock, says what it dropped and the PID, and stops nothing; an unknown ID exits 2 and lists the kept IDs. The refusals, the hold's warning and `uak lock status` name it with the hold's ID, and say the PID may have been reused; use it only once the process is known to be gone or its PID known to be reused, as a build that really still runs could write mutant objects past the stamp. On Linux a zombie now counts as gone everywhere uak checks a process.
- A kept record is no longer dropped because a clock step moved a live command's start time on Linux: its start time matches within 60 s, not 1 s.
- A kept record that can't be read, or `<State>/Lock/Orphans/` that can't be listed, is warned about by name, not skipped in silence.
- UBA's "Exited with error code N. This action will retry" lines no longer count as a failure: a retried action that passed took a failed build's compiles from the evidence.

### Changed

- The `uak mutate` help, DESIGN.md, the README, the workflow skill and the worker and runner definitions describe the stamp, `BINARIES PENDING` and the new meaning of exit 5 (the files not put back, or not stamped).
- `uak mutate -restore` refuses (exit 2, nothing changed), each time, while the killed check's build still runs after the lock's 30 s wait for it, until that process has gone; so does a new `uak mutate`, whose stamp that build could write objects past. The lock now remembers such a command across holds, in `<State>/Lock/Orphans/`, until the process with that start time has gone and its job is empty: every hold waits for it again (30 s at most) and warns, and `uak lock status` lists it. A hung one costs each hold 30 s until someone stops it, as the warning says, or `uak lock forget-orphan` drops its record; other commands go ahead after the wait.
- A failed rebuild counts as evidence only when each failure in its log is laid on an action: a failure no pattern parses (`c1xx: fatal error`, a compiler's command-line error, a crash, UBT's own "Exited with error code") takes every compile of that build from the evidence, and the journal waits for another build. A mutant build that failed with no `Result:` line and no parsed error leaves what it compiled and linked unknown, so the journal waits for every patched source and for a build that shows them. A `-restore -accept` that compiled nothing passes only a whole list of the folder's own run that names no source.
- `.m` and `.mm` sources, and `.isph`, `.ipp`, `.tpp` and `.def`, which a compile reaches by `#include`, count as files a compile must show, and so do `.swift`, `.proto` and `.rc`, shown by any compile, as no compile item is named exactly after one. `.S` and `.asm` don't: UBT compiles neither.
- A stamp that fell back to writing a file whole touches its attributes only when the read-only, hidden or system one is set, and every stamp deletes the temporary files a killed run left beside its files. A stamp that throws no longer ends the run before its verdict: the journal stays and it exits 5.
- A run record that names another run, or lists a file without a full path, no longer passes `uak vcs shelve` and `uak horde preflight -shelve` as a journal whose files are back.
- Publish `uak` again for 0.4.1 (the SessionStart hook offers to), and have every agent use it before the next `uak mutate`.

## 0.4.0

### Added

- **The tree a run found.** `uak build` and `uak test` (editor and `-cooked`) read the version-control state once they hold the lock, alongside the run (so a slow server never holds the lock up; after 30 s it is `unknown`), print it as the summary's first line and write it to the result file as `Tree`: the revision (as `uak vcs revision` gives it) and the changed files (as `uak vcs changed` lists them), or, above 10 files, their count and a short hash. The hash covers each changed file's state, path and content (past 200 files, or for a file over 16 MiB, its size and write time), so it tells two trees in one workspace apart. It is no fingerprint across machines: it hashes the bytes as checked out (CRLF and LF checkouts differ), Git's index is not part of it, and Perforce lists only opened files (a writable file that isn't opened counts as unmodified). Nor is it proof of what was built or tested: an editor test builds nothing, `-cooked -skipbuild -skipcook` tests a game staged earlier, and an edit made during the run isn't seen. Git, Perforce and none; a failed query prints `tree: unknown (...)` and never fails the run.
- **`uak mutate -name=<unique> -patch=<diff> -filter=<filter> [test options] [-resultfile=<path>]`**, a guarded mutation check. Under one hold of the editor lock it applies the patch (`git apply` in a Git workspace, after checking that git reads the same files and +/- lines as uak; else a strict unified-diff applier that keeps every line it doesn't add as it is, its bytes and line end (an added line gets the kind most of the file's lines have), and refuses a line a hunk's header doesn't count; either way each hunk must match exactly at the line its header names, and its header's new start must agree, since git starts its search there and searches otherwise than a search here would: there is no search for moved lines; a hunk without context lines after its changes must end at the file's end, where git applies one; and in a Git workspace `git apply --check -v` must apply every hunk at its header's line (git compares a line's `\r` under `core.autocrlf=false`, where uak doesn't), so uak's plan is git's lines; a file with CRLF line ends under `core.autocrlf=false` needs a patch with CRLF ones, as `git diff` writes there), prints each file's +/- lines, builds the editor target, runs the editor tests, then always puts every touched file back, byte for byte, and rebuilds, even when the build or tests fail or on Ctrl+C. A file with uncommitted changes can be patched (the copy keeps them), so there is no need to commit first. It refuses (exit 2) when the patch can't be read, doesn't apply cleanly or changes nothing, when a file it creates exists, when a file it changes or deletes is a symbolic link or one of several hard links to one file (writing it whole would replace the link, or part the names), when it renames, copies or changes binary files, when a file can't be copied first or the journal's folder can't be made (nothing is left behind), when a folder of its name with no journal in it can't be deleted, or when a file changes while the patch is written (uak's applier checks each file just before it writes it: the files written are put back, the changed one is left alone; it writes each file whole, through a temporary file renamed over it, and puts one whose write fails back at once while it holds exactly the run's own bytes, saving them first, but leaves anything else). `git apply` writes every file after one check, so an edit can get in before git reads a file. When git then refuses the patch (a hunk no longer applies, a file to change is gone, or one to create exists: git checks every file before it writes anything, and uak runs it in the C locale to read its message, taking it for a refusal only when every error it printed is one of those), git wrote nothing: a file that holds neither its original bytes nor the patch's is that edit, left as it is, and the run is refused (exit 2) with its journal cleared. When git applies it over the edit, a file that then holds neither (line ends aside) is left in place, with its bytes saved beside the journal, and the check ends with no verdict and exit 5 (`-restore -accept` then merges the mutation out of it, or refuses it); a file whose bytes uak couldn't predict for git (one that isn't UTF-8 text) has its bytes saved too. The verdict needs a test result: 0 caught (a test, or a listed test, completed with `Result={Fail}`), 6 survived (not 1, which a killed run exits with), 3 the mutant didn't build (an error in a patched file or one whose `#include` names a patched header), 4 inconclusive (the build shows no compile of a patched source file, by its name or in its module's `Module.<module>.cpp` unity file (named after the `ShortName` its `Build.cs` sets, if any; UBT's `[Cache]`, `[NoUba]` and `[RemoteExecutor: host]` tags, and its optional target and times, are no part of the name), or none at all for a patched header, or failed elsewhere; or the tests ended badly, or skipped a listed test, without a failed test), 5 restore failed (the message says whether the files or only the rebuild), 1 no verdict, 2 refused. `-resultfile` holds the check's own verdict, written at every exit. A compile matched by the file's name alone, while the project has another file of that name, is warned about: it may be the other's. Run the same tests green first, and patch only files no other agent is editing: the mutation is in the shared tree for the whole run, so until the check ends, even one running detached, nobody edits those files or relies on reading them (an edit made then is made over the mutant).
- **The mutation journal.** Before the patch is applied, each file is copied to `<State>/Mutations/<name>/` (as `<n>.<file name>.orig`) and recorded with its hash, and so are the patch (`patch.diff`) and the hashes it is to give each file, all flushed to the disk; the journal is written in `<State>/MutationsPending/` and renamed into place whole, and renamed out again before it is deleted, so `uak compile`, which reads it without the lock, never sees half of one; one that can't be renamed (a reader holds a file in it open) is left whole, never deleted in place: the check's verdict stands, with a warning, and `-restore` clears it (exiting 5 while it can't). If uak is killed, the journal stays, and `uak test` and `uak lock run` refuse to run on the tree, and `uak build` and `uak compile` until the files are back, until `uak mutate -restore [-name=]` (run on its own, not inside `uak lock run`) puts back each file that still holds the mutation, or, for a run killed while it wrote the patch, the bytes the patch was to give it (a copy is written back only when its hash matches, and a file only while it still holds the bytes it was judged by, after saving what it held when it is saved, and whole, through a temporary file renamed over it, keeping its attributes), rebuilds and clears it. A file of a run killed while it wrote the patch that holds anything else may hold part of it: only `-force` puts it back, and `-accept` refuses to keep it. A journal that can't be read (a truncated or empty `journal.json`, an unknown phase, copies without a journal) is refused the same way, never skipped. A journal is a live run's only for the process that joined that run's own hold (its ID and start time both read and matched), so a protected process that reuses a killed run's ID never hides it. A file changed since the patch was applied is left and reported: an edit made while the check ran is made over the mutant, and may keep it. A file that became a link since (a hard link made to it, or a symbolic link in its place) is left in every mode, as uak never writes a link, and the hint says to remove the other link first. Then `-restore -name= -accept` merges such an edit three ways: the mutant (the patch applied to the journal's copy of the original) as the base, the file as it is, and the original, and takes the mutation out only where it is pinned and the edit left the lines around it alone. Each change of the patch is pinned to its anchor: the lines around it, grown up and down until, each way, the block occurs once in the mutant. A strict near-edit rule then refuses the file when the edit changed, copied, moved or deleted any line of an anchor or of its neighbours (the line before and after it, or the file's start or end where it reaches one), judged by comparing the mutant and the file around the anchor: the anchor with its neighbours must be in the file exactly once, byte for byte as in the mutant (a line end's `\r` aside only on the lines the patch added, whose line end the applier chose, and in a file that has one kind of line end) and nowhere else even with the `\r`s aside; both ways of lining the edit up with the mutant (as early and as late as a shortest edit script can) must keep each of its lines in place; none of its lines, the mutated ones among them, may be in the file more often than in the mutant (a copy; a line of punctuation alone, such as `};` or `);`, isn't counted, but a blank line and a brace alone are, as without them review 6's fuzzer finds kept mutations again); and no line the change pins (a mutated line, or the line before and after lines it only removed) may be like another of its lines (a brace next to a brace, a blank line next to a blank line), which an edit could swap it with without changing a byte. Its refusal says which lines the edit touched and offers `-force`. With that, a clean merge (the edit and the mutation change different lines, with an unchanged line between) with no place both sides changed alike (the mutation taken out by hand), no copy of the mutated lines (the merge holds them, with the line before and after, or a non-blank one on its own, no more often than the original does: the edit may have copied the mutation, or written such a line itself), and the same result both ways takes the mutation out of that block and keeps the edit (what the file held is saved beside the journal first). The merge is kept for edits elsewhere, and the cost is in refusals: an edit next to the mutation is refused, even one that only edits the mutated function's signature, and so is one anywhere in the file that copies a line of the anchor or its neighbours (a function added anywhere copies the braces most anchors hold), and anything else uak can't place for sure, saying why; on review 6's fuzzer -accept keeps about 4.5% of edited files where it kept about 18%. A file the patch created or deleted is never kept once edited. For a refused file, `-force` puts the originals back over every file, saving what it overwrites beside the journal (as `<n>.<UTC time>.current`, never over bytes saved before), so a refused edit can be made again on the original from there; both rebuild and move the journal to `<State>/DiscardedMutations/`. While a check runs, another agent's `uak compile` warns that it compiles the mutant. **`uak mutate -status`** lists the journals left, running or killed, without the lock, and exits 0 when none is, 5 when one is: commit, shelve or preflight only once it exits 0. `uak vcs shelve` and `uak horde preflight -shelve` refuse while a journal is left (a running check's too: its patch is in the files, and the shelf would ship it), and warn that they can't look when no project is found from where they run (the journals are in the project's state folder), and `uak vcs status` and `uak vcs changed` warn, naming its files. **Switch every agent to 0.4.0 before the first `uak mutate`**: an older `uak` doesn't know the journal.
- **`uak test -watch=<LogCategory>[,...]`** prints each category's Error and Warning counts in the run's log (`Client.log` for a cooked run). The automation framework logs a message a test expects at Verbose, so only real Errors and Warnings count.
- **`uak runs show -name=<run>`** prints a finished run's end and the summaries its `uak build`, `uak test` and `uak mutate` recorded (tree, watched categories, expect check, problems, verdict), without reading its log. It also shows the last summary of a direct `uak test -name=` (and `uak build -name=`, a new option), for any name those take. Summaries are kept in `<State>/Summaries/`; detached runs pass their name to their command in `UAK_RUN_NAME`, and commands of one run that end together each keep theirs. Each entry names the command run that recorded it (an ID, and its process): a command drops its name's results as it starts, and records its result, or a refusal or failure, only in its own entry's place, so a command that is still running, was refused or was killed never shows an earlier command's result (`runs show` says it "recorded no result", and whether its process still runs; `runs wait` prints `Verdict: none`), and two commands that run under one name at once (the default names `uak-build`, `uak-test` and `uak-test-cooked` are every command's that has no `-name=`) each keep their own entry, listed with its process ID; they also share the test log named after the name, which each test run replaces as it starts, and `runs show` says so. An entry recorded without its command run's ID never takes another's place, and a command counts as still running only while its process ID runs with the start time it recorded (an unknown start time counts as gone). Runs and commands share the names: a command started directly with `-name=X` drops run X's results, and `uak runs start -name=X` clears command X's.
- **Filter warnings.** `uak test` warns when a `-filter` part matches none of the tests found, and when a part without a trailing `.` also matches tests under another name (`Game` running `GameBench.*`).
- **`uak test -quiet`, for benchmarks.** It refuses to start while others wait for the editor lock, and holds the lock as a quiet hold: while it runs, `uak compile`, which otherwise needs no lock, waits too, and compiles already running finish before it starts (after 10 minutes it goes ahead, with a warning); a compile waits for it at most 30 minutes, then compiles with a warning. It refuses (exit 2) inside another hold that isn't quiet (`uak lock run -- uak test -quiet`), and fails (exit 1) when it can't record its quiet hold. A quiet holder or compile whose start time can't be read counts as gone, so a killed one whose ID is reused never stops compiles.
- **`uak test config -cooked-maps=<a+b+...>`** saves the maps `uak test -cooked` cooks when `-map=` isn't given, per project, in `<State>/config.json`. `uak test config` alone prints them; `-reset` forgets them.
- **The `review-diff` agent**, a read-only reviewer for scoped re-reviews, on the lead's model at high effort (not pinned to Opus). Given a fix diff (or commit range) and the findings it is meant to fix, it checks that each finding is fixed and hunts for new issues the diff introduced, without reviewing the rest of the project. It reports findings ranked critical, major, minor or nit, confirmed or plausible, with evidence, says plainly whether any critical or major issue is left, and says what it didn't check. The workflow skill's tier table lists it (default cap 2), and so do the README, DESIGN.md, INSTALL.md and the CLAUDE.md snippet; the `high`, `xhigh` and `review` descriptions point to it for re-reviews of a fix.

### Changed

- **`-expect` reports unexpected tests apart from failures.** A run whose listed tests all passed, but which also completed tests the file doesn't list, was FAILED (exit 1). It now says, for example, `test: PASSED: 242 of 242 listed passed; 2 unexpected (2 passed); ...` and exits 3; `-allow-unexpected` makes it 0. A missing or failed listed test, and a failed unexpected one, still fail the run (exit 1). The result file's `Outcome` is `unexpected tests` for exit 3.
- **Memory-aware `uak compile -dependents`.** A given `-MaxParallelActions` (or `UAK_MAX_PARALLEL_ACTIONS`) is lowered to one action per 1.5 GiB of free memory, as UBT limits its own default (UE 5.8 `Utils.GetMaxActionsToExecuteInParallel`), a limit UBT drops once a value is given.
- The worker and runner definitions show `-watch=`, the new `-expect` exit code and `uak runs show`, use `uak mutate` for mutation checks (never a hand edit, build and revert while other agents build; a green baseline first, only files no other agent edits, none of them edited or relied on by the worker itself until its check ends, `uak runs start` for a long check), read a run's own exit code and verdict line from `uak runs wait`, and use `-quiet` for benchmarks. Workers commit, shelve or preflight only once `uak mutate -status` exits 0, and the workflow skill's "pass, then commit" step waits for it too. The workflow skill's command list and the project README template have the new commands, and the skill's restart section says what to do when a stopped agent refuses a SendMessage ("won't be resumed"): respawn it from its brief and have the new agent review the uncommitted diff first.
- **`-resultfile` of `uak build`, `uak test` and `uak compile`** is deleted as the command starts, and a command refused or stopped before it writes its result writes `{ Command, Outcome: "refused" | "stopped", ExitCode, Message }`, so an earlier run's result is never read as this one's; an editor test whose editor wrote no log writes its failed result too.
- **UBT's action lines** are read with UE 5.8's additions: where an action ran after its item (`[Cache]`, `[NoUba]`, `[RemoteExecutor: host]`), and, when configured, the target and the action's times after the count, none of them part of the item.
- **`uak runs wait`** also prints the verdict line of the run's last `uak build`, `uak test` or `uak mutate`, with that command's exit code: its own exit code stays 1 for any code but 0, which for `uak mutate` may be a result (6 survived).
- **`-name=`** of `uak test`, `uak build` and `uak mutate` must be a plain file name without white space, control characters, path separators or `: * ? " < > |`, that doesn't end in `.` and isn't a Windows device name (`CON`, `NUL`, `COM1`, ..., with or without an extension), on every platform (it names the log, the summary and, for `uak mutate`, the journal, whose folder Windows would otherwise name differently).
- **The workflow skill's cost guidance.** `xhigh`, `research`, `review` and `architect` run on Opus whatever the lead runs on, so they are the expensive tiers: the skill now gives `xhigh` only formats, contracts and correctness-critical algorithms (their fix passes go to `high`), runs `research` at its default effort unless the answer pins down an engine fact the design rests on, and keeps `review` for a milestone's or a plan's first review. The review loop (review, fix, re-review until no critical or major finding is left) runs its re-reviews with `review-diff`, scoped to the fix diff and the findings it fixes. After a usage limit or a Claude Code restart, the skill prefers respawning an agent from its brief to resuming it, since a resume replays the agent's whole transcript. And the lead restarts at milestone boundaries: it can't clear its own context, which every turn re-sends, so it writes a handoff (state, next steps, running agents and runs, pending decisions) into its memory and the project's files, and tells the user to run `/clear` and continue.
- **One severity scale for reviews.** `review` now ranks findings critical (the project's worst failure class), major (a correctness bug or contract violation), minor (a gap in the tests or verification, or a claim the evidence does not support) and nit (style, wording, docs), as `review-diff` does. The epic brief template names a suggested tier by the kit's short agent names (`low`, `medium`, `high`, `xhigh`), not the old `ue-` ones.
- INSTALL.md says that a second Claude config profile needs the plugin installed and enabled there too, or the kit's agent types are missing.
- Publish `uak` again for 0.4.0 (the SessionStart hook offers to), and have every agent use it before anyone runs `uak mutate`.

## 0.3.6

### Added

- **Compaction loops.** An agent whose context fills compacts and carries on; if it then reads the same large files again, it fills again soon after, and can loop for hours without editing, running or handing back. The workflow skill's "Resume or respawn" section now tells the lead how to check an agent that runs long (count `compact_boundary` entries in its transcript, and see when its files last changed and when it last built or tested), how to stop a loop (the agent writes its brief and splits the rest of its step; each part is respawned as its own agent), and how to prevent one (steps sized to one context, short briefs, sections named in the spawn prompt).
- **Read large files in parts.** The worker definitions (`low`, `medium`, `high`, `xhigh`) and `research`, `review` and `architect` read long files by section (Grep, then `offset` and `limit`), grep logs rather than read them whole, and re-read only what the next action needs after a compaction. A worker whose task won't fit in one context finishes and verifies a first part, writes down the rest, and hands back.

### Changed

- The brief template's Current state asks to keep it short; the history belongs in version control.
- `uak` itself is unchanged, but its publish folder follows the kit's version: publish it again for 0.3.6 (the SessionStart hook offers to).

## 0.3.5

### Added

- **`uak test -cooked`** runs automation tests in a cooked game: under the editor lock, UAT's BuildCookRun (the engine's `RunUAT` script) builds the game, cooks, stages and paks the project, and runs the game with `-nullrhi -RunAutomationTest=<filter>` until the test queue empties. `-skipbuild` reuses the game's binaries and `-skipcook` the staged build; `-map=` names the maps to cook (the first is opened), `-config=` the configuration (Debug, DebugGame, Development or Test), `-timeout=` the run's limit (default 1800 s). Game arguments after `--` go through `-addcmdline` (`-ExecCmds`, `-testexit`, `-abslog`, `-ReportExportPath`, quotes and `% ! & | < > ^` are rejected). The game's log is `<Project>/Saved/Logs/<name>/Client.log` and UAT's output `<Project>/Saved/Logs/<name>.log`, both printed first. A cooked run passes only when UAT exited 0, `Client.log` ends its queue with `EXIT CODE: 0`, no test failed, every found test completed, at least one passed, and the run didn't time out; the game's own exit code is printed, not judged.
- **`uak test -expect=<file>`** (editor and cooked runs) lists the tests a run must pass, one full test name per line (blank lines and `#` comments ignored). A run expects the listed names its `-filter` matches, matched as the engine matches filters (`StartsWith:`, `^`, `$`, `+`; `Group:` is rejected), and passes only when each of them passed and no other test completed. Missing and unexpected tests are printed one per line.

### Fixed

- **A found test that never completed is listed and counted as skipped.** The engine skips a test that needs more participants than the run has without a `Test Completed` line, and still ends the queue with exit code 0. `uak test` failed such a run (found 1, completed 0) but reported 0 skipped. It now lists the test as `NotRun <name>` (from the found tests the engine logs after `Found N automation tests`) and counts it as skipped, so a run whose only test never ran is NOTHING RAN. The result file has the names in `NotRun`.

### Changed

- `uak test`'s result file has `Mode` (`editor` or `cooked`), `NotRun` and `Expect`.
- The worker and runner agents' definitions show `-cooked` and `-expect=<file>` in their `uak test` usage, with the `MSYS_NO_PATHCONV=1` note for `-map=/Game/...` from Git Bash.
- Publish `uak` again for 0.3.5 (the SessionStart hook offers to).

## 0.3.3

### Changed

- **Shelving replaces the shelf by default.** `uak vcs shelve -c=<N>` and `uak horde preflight -shelve` now run `p4 shelve -r`, so the shelf becomes exactly the files opened in the changelist. Before, they ran `p4 shelve -f`, which left files that were reverted or moved out of the changelist on the shelf: a preflight built them, and a Horde auto-submit would have submitted them.
  - Every file the shelf loses is printed ("REMOVED from the shelf"; `removed` in the JSON, now also in `uak horde preflight -json`).
  - Shelving a changelist with nothing opened is still refused: `-r` would empty the shelf.
  - A file that leaves the changelist while uak shelves still fails the command, naming it.
- **`-keep-unopened`** on both commands brings back `p4 shelve -f`: shelved files that are no longer opened stay on the shelf, listed as kept. Use it when the shelf is the only copy of that work.
- **`-replace` and `-drop-unopened`** on `uak vcs shelve` are accepted and do nothing, so older scripts keep working.
- **`-allow-shelved-only`** on `uak horde preflight` now needs `-shelve -keep-unopened -autosubmit`. Without `-keep-unopened` the files it would let Horde submit are deleted from the shelf instead, so the old `-shelve -autosubmit -allow-shelved-only` is a usage error rather than a silent change. The refusal to auto-submit shelved files that aren't opened applies only with `-keep-unopened`.

## 0.3.2

### Added

- **`uak horde log -job=<id>`:** a Horde job's errors and warnings, without reading whole logs. It reads the events Horde found in the steps' logs (each with its severity), not the log text, and prints per step one line (outcome, counts, the log's URL), then each distinct event with its line number, how often it occurred, and the lines before it. Errors come first; an event repeated within a step, or already shown under an earlier step, is only counted.
  - Without `-step=`, the failed steps, then those with warnings. `-step=` takes a step id or name (or part of a name).
  - `-errors` or `-warnings` keeps one severity; `-max=` (default 10) caps the distinct events per step; `-context=` sets the lines before each event (default 2 before errors, none before warnings); `-json` for scripts.
  - `-save` also saves each step's whole log as text in the state folder (`Logs/horde/<job>/`) and prints where.
  - Exit codes are those of `uak horde job`: the job's result (0, 1, 3, 7), 4 not signed in, 5 another error (no such job or step).
- **`-issues`** on `uak horde job` and `uak horde preflight -wait`: the same report, with the defaults, after the summary.

### Added

- **`architect` agent:** drafts a milestone's plan, briefs README and epic briefs from the workflow skill's templates, with a file-ownership map, contracts, suggested tiers, and risks with their tests. It writes only those drafts and runs nothing. Default cap 1.
- **Perforce writes:** `uak vcs shelve`, `uak vcs edit`, `uak vcs add`, `uak vcs reopen`, `uak vcs change new` and `uak vcs change describe`, on this client's pending changelists only. Nothing reverts or submits. `shelve -replace` refuses to delete shelved files that aren't opened unless `-drop-unopened`, prints what the shelf loses, and fails, naming it, when it loses a file nobody asked to drop; every shelve lists shelved files that changed and those kept although no longer opened. `shelve -c=` is refused while an auto-submit Horde preflight of the change runs (when a Horde server is configured; a warning when Horde can't be asked). Half moves are refused; a description change puts back files a concurrent reopen moved in or out, or moves none and says so when it can't tell which.
- **Horde:** `uak horde config`, `uak horde login`, `uak horde logout`, `uak horde streams`, `uak horde templates`, `uak horde preflight` and `uak horde job`, on the engine's prebuilt EpicGames.Horde.
  - The server is set once per user in `~/.unreal-agent-kit/config.json`.
  - Commands sign in silently, else open the Horde sign-in page and wait (`-login-timeout=`, default 600 s; `-no-login` for CI).
  - A preflight prints its job URL at once, and auto-submits only with `-autosubmit`. Without `-shelve` it reports ("reused: <job>") a still-running preflight that uak started, with the same stream, template, parameters and auto-submit setting, created after the change was last shelved and on the same shelf (uak records each preflight it starts), instead of starting another; with `-shelve` it always starts a new one. Horde submits the change's current shelf, so uak won't shelve under a running auto-submit preflight, won't start a second auto-submit preflight of a change, and with `-shelve -autosubmit` won't auto-submit shelved files that aren't opened (`-allow-shelved-only`); these refusals exit 5.
  - `-wait` waits quietly and ends with a short summary and exit codes for agents (0 success, 1 failure, 2 usage error, 3 still running, 4 not signed in, 5 error, 6 build settings needed, 7 warnings).
  - `uak horde config -open=` can open the job's page in the browser.
  - Build settings per server and stream (`~/.unreal-agent-kit/horde/<server>/<stream>/templates.json`): a template and its parameters, saved with `uak horde config -template= -param:<id>=`. A preflight with none saved starts nothing and exits 6 with the templates and parameters, so the lead asks the user. `-template=`/`-param:` change one run; `-use-template-defaults` for CI.
  - On Windows, the access token is cached per server (`~/.unreal-agent-kit/horde/<server>/token.bin`, DPAPI for the current user) until 5 minutes before it expires; a refused token is deleted, and the command signs in again and retries only the refused request, once. A wait that rebuilds its connection keeps Horde's own self-refreshing sign-in, and a sign-in mid-wait ends at the wait's `-timeout`. A token from `UE_HORDE_TOKEN` is never cached. `uak horde logout` deletes it.
